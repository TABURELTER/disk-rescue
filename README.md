# Disk Rescue

Восстановление файлов в Windows через терминальное меню: создание сырого образа, поиск файловых систем, просмотр файлов и экспорт с именами и папками, когда сохранились метаданные. Работает на базе **The Sleuth Kit 4.15.0** и **PhotoRec 7.2**.

**Windows 10 1903+ / Windows 11 · x64 · Windows PowerShell 5.1+**

[Скачать релиз](https://github.com/TABURELTER/disk-rescue/releases/latest) · [Инструкция](docs/USAGE.md) · [Проверки и ограничения](docs/VERIFICATION.md) · [Лицензии компонентов](THIRD_PARTY_NOTICES.md)

## Запуск одной командой

Откройте **PowerShell** и выполните:

```powershell
irm 'https://raw.githubusercontent.com/TABURELTER/disk-rescue/main/install.ps1' | iex
```

Команда загружает установщик из этого репозитория. Он скачивает релиз **v2.1.0**, проверяет SHA-256 архива, распаковывает программу в `%LOCALAPPDATA%\DiskRescue` и открывает терминальное меню. Интернет нужен для загрузки; установленная программа работает офлайн. Git, Python и отдельная установка движков пользователю не нужны.

`iex` выполняет скачанный код. Просмотреть его можно в [install.ps1](install.ps1). Хеши проверяют целостность загрузки в рамках доверия к этому GitHub-репозиторию и его релизам; это не независимая цифровая подпись.

Для работы с **готовым образом** права администратора не нужны. Для чтения **физического диска** запустите установленный `START.cmd` от имени администратора. Установщик не повышает права автоматически. Устанавливайте программу на исправный диск, отличный от восстанавливаемого носителя.

### Скачать вручную

1. Скачайте `DiskRescue-win-x64.zip` со [страницы релиза](https://github.com/TABURELTER/disk-rescue/releases/latest).
2. Распакуйте, например в `C:\DiskRescue` на исправном диске.
3. Запустите `START.cmd`.

Самостоятельный `Recover-Disk.ps1` также содержит движки. При ручной загрузке контрольные суммы доступны в `SHA256SUMS.txt` и `SHA256SUMS.json` соответствующего релиза:

```powershell
Get-FileHash 'C:\DiskRescue\DiskRescue-win-x64.zip' -Algorithm SHA256
```

## Что умеет

- Выбор обычного несистемного HDD, SSD или USB-носителя и создание полного образа только чтением.
- Открытие одного сырого образа `.img`, `.dd` или `.raw`.
- Быстрый поиск разделов MBR/GPT; полный проход по загрузочным секторам FAT, exFAT и NTFS.
- Постраничный список файлов с поиском по части пути.
- Восстановление всех, существующих или удалённых файлов через метаданные файловой системы.
- Сохранение вложенных папок, Unicode-имён, пустых файлов и директорий, если это позволяют метаданные.
- Отдельный поиск PhotoRec по сигнатурам, когда обычный экспорт невозможен.
- CSV-отчёт об исходных и фактических путях, переименованиях, пропусках и ошибках.
- Чтение сведений из пользовательского лога DMDE через `-LogPath`.

Основные испытанные файловые системы: **FAT16, FAT32, exFAT и NTFS**. Чтение других файловых систем зависит от The Sleuth Kit. Полный поиск реализован только для FAT/exFAT/NTFS.

## Как устроено восстановление

```text
Физический диск ── чтение ──> disk.img ── поиск ФС ──> список файлов
                                  │                         │
                                  │                         └─> экспорт имён и папок
                                  └─> PhotoRec ────────────────> файлы по сигнатурам
```

Сначала создайте образ на **другом физическом диске**. Затем сканируйте образ, выберите файловую систему, просмотрите найденные пути и запустите экспорт. Образ занимает столько же места, сколько весь исходный диск; восстановленным файлам нужно дополнительное место. Другой раздел того же исходного диска назначением быть не может.

Результаты каждого экспорта получают новый каталог:

```text
сеанс/
├── disk.img
├── image-info.json
├── volumes.json
├── recovered-tree-0001/
│   ├── files/                 # Восстановленное дерево
│   ├── filesystem-index.tsv
│   └── recovery-manifest.csv
└── carving-0001/              # Отдельный результат PhotoRec
```

**Исходная структура восстанавливается только из сохранившихся метаданных.** Если потеряна связь с родительской папкой, файл может попасть в `$OrphanFiles`. Если имена и дерево уничтожены, PhotoRec извлечёт содержимое без исходных имён и папок. Успешный экспорт и совпадение размера сами по себе не доказывают целостность файла.

## Защита источника и пределы

Модуль создания образа открывает физический диск с `GENERIC_READ` и `OPEN_EXISTING`. В оболочке нет команд форматирования, ремонта файловой системы или записи секторов. Она проверяет выбранное устройство и блокирует назначение, временные файлы и размещение программы на исходном физическом диске.

При ошибке чтения сохраняется `disk.img.partial`; образ не объявляется полным. Автоматического пропуска повреждённых секторов и возобновления чтения пока нет. Отмена выполняется после завершения текущего системного запроса.

Windows и другие процессы могут записывать на подключённый носитель независимо от Disk Rescue. Аппаратный блокиратор записи защищает и от такой записи. Последовательный образ смонтированного диска не является согласованным снимком. Чтение физически неисправного носителя также несёт риск; успешная работа с настоящими физическими устройствами в проверках этой версии **не испытана**.

Ограничения:

- Системный и загрузочный диск работающей Windows не копируются; для них нужен подготовленный офлайн-образ.
- RAID, Storage Spaces, виртуальные и составные диски не реконструируются.
- Автоматического снятия шифрования, поддержки E01 и составных образов в интерфейсе нет.
- Назначение должно быть локальным томом NTFS/ReFS; сетевые пути, junction и неоднозначные точки монтирования отклоняются.
- NTFS ADS, символические ссылки и специальные файлы пропускаются; исходные ACL, атрибуты и временные метки полностью не воссоздаются.
- Перезаписанные данные и данные после TRIM могут быть утрачены окончательно.

Это программа восстановления с ограниченным набором сценариев, а не полная замена DMDE. Связи с разработчиком DMDE у проекта нет.

## Командная строка

Сканирование готового образа:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'C:\DiskRescue\Recover-Disk.ps1' -Action Scan -ImagePath 'D:\Backup\disk.img' -OutputDirectory 'E:\Scan-01' -DeepScan
```

Экспорт найденной файловой системы с именами и папками:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'C:\DiskRescue\Recover-Disk.ps1' -Action Recover -ImagePath 'D:\Backup\disk.img' -OutputDirectory 'E:\Recovery-01' -Offset 2048 -RecoveryMode All
```

`-Offset` задаётся **в секторах** и берётся из отчёта сканирования; `2048` здесь только пример. `-RecoveryMode` принимает `All`, `Allocated` или `Deleted`. Размер сектора по умолчанию — 512 байт; при необходимости передайте `-SectorSize 4096`. Каталог назначения должен быть новым. `ExecutionPolicy Bypass` действует только для запускаемого процесса.

Анализ собственного лога DMDE:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'C:\DiskRescue\Recover-Disk.ps1' -Action Analyze -LogPath 'C:\DiskRescue\fullscan.log'
```

Лог не заменяет образ диска и не содержит сами восстанавливаемые файлы. Код и команды из лога не выполняются. Сжатые результаты сканирования DMDE этой оболочкой не декодируются. Чужие логи и идентификаторы носителей в публичную сборку не включены.

## Исходники, сборка и проверки

Исходный PowerShell-код и нативный модуль находятся в `src/`, сборщик — в `scripts/build.py`, архив движков — в `assets/engines.zip`. Пользовательская программа собирается в один `Recover-Disk.ps1` со встроенным архивом движков. Сведения о происхождении и изменении ресурсов EXE прилагаются к сборке и находятся внутри движков.

Для сборки из исходников нужен Python 3.11+; сборка использует стандартную библиотеку и не скачивает зависимости:

```powershell
python scripts/build.py
python tests/check_public.py --dist dist
python tests/smoke.py --report dist/TEST-RESULTS.json
```

Последняя команда требует поддерживаемую Windows и PowerShell; она использует только тестовые образы. Подробнее — [tests/README.md](tests/README.md). Воспроизводимый патч ресурсов четырёх TSK EXE находится в `tools/manifest-patches/`.

В ходе разработки проверены содержимое и пути файлов на синтетических FAT/exFAT-образах, официальном NTFS-образе с удалёнными файлами, конфликтующих именах, а также экспорт PNG/ZIP через PhotoRec. Контрольные суммы исходных образов до и после совпали. Подробная область проверок и непроверенные сценарии — в [docs/VERIFICATION.md](docs/VERIFICATION.md). Данные о конкретном релизном артефакте — в `BUILD-INFO.json` и отчётах релиза.

Не прикладывайте к публичным issues образы дисков, восстановленные файлы, логи с персональными данными или серийными номерами. Для описания ошибки достаточно версии, файловой системы, текста ошибки и обезличенного примера пути.
