# Инструкция Disk Rescue 2.1

## Установка и запуск

В PowerShell:

```powershell
irm 'https://raw.githubusercontent.com/TABURELTER/disk-rescue/refs/heads/main/install.ps1' | iex
```

Установщик загружает закреплённый релиз v2.1.0, сверяет SHA-256 и запускает установленный скрипт в отдельном процессе PowerShell. Программа устанавливается для текущего пользователя в `%LOCALAPPDATA%\DiskRescue`; системная политика выполнения не меняется. Повторный запуск установщика открывает программу без необходимости вручную искать архив.

Для управления установкой сохраните [install.ps1](../install.ps1) в удобную папку и запустите его с параметрами:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -InstallRoot 'C:\DiskRescue' -NoLaunch
```

`-Version v2.1.0` выбирает конкретный релиз. `-Version latest` выбирает последний опубликованный стабильный релиз. Без параметра версия закреплена в установщике. Для исходного носителя, который читается как физический диск, папка установки, временный каталог и папка результатов должны находиться на другом физическом диске.

Без установщика скачайте `DiskRescue-win-x64.zip` из [GitHub Releases](https://github.com/TABURELTER/disk-rescue/releases/latest), распакуйте и запустите `START.cmd`. Готовый образ можно обрабатывать без администратора. Для чтения физического диска запустите `START.cmd` от имени администратора.

## Главное меню

| Пункт | Действие |
| --- | --- |
| Создать образ | Показывает доступные обычные HDD/SSD/USB и копирует выбранный носитель чтением |
| Открыть образ | Принимает один полный сырой `.img`, `.dd` или `.raw` |
| Сведения DMDE | Анализирует лог, указанный пользователем через `-LogPath` |
| Возможности | Показывает поддерживаемые сценарии и ограничения |
| Выход | Завершает программу |

Номер устройства из лога DMDE никогда не используется для автоматического выбора источника. Выбирайте устройство по актуальной модели, размеру и идентификаторам в списке, затем подтверждайте конкретный номер.

## Создание образа

1. Выберите физический диск и проверьте его сведения.
2. Задайте **новую папку на другом физическом диске**.
3. Введите запрошенное подтверждение вида `DISK 2`, используя фактический номер.
4. Дождитесь завершения чтения. Затем работайте с созданным `disk.img`.

Под образ нужен полный размер исходного устройства плюс резерв программы. Восстановленные файлы занимают дополнительное место, которое не включено в предварительное резервирование всего будущего экспорта. Для большого носителя заранее выберите диск с достаточным запасом.

Пока чтение не завершено, файл имеет имя `disk.img.partial`. После полного чтения он переименовывается в `disk.img`; сведения и SHA-256 записываются в `image-info.json`. При ошибке остаются `.partial` и признак незавершённости. Повторное чтение с продолжением не реализовано. `Q` или `Esc` отменяет операцию после завершения текущего запроса чтения; аппаратный сбой может задерживать этот запрос.

## Поиск и экспорт

1. Запустите **быстрый поиск** по таблице разделов и началу образа.
2. Если нужная файловая система не найдена, запустите **полный поиск** загрузочных секторов FAT/exFAT/NTFS.
3. Выберите кандидат и просмотрите список файлов. `n` — следующая страница, `p` — предыдущая, `f` — поиск, `q` — возврат.
4. Выберите экспорт всех, только существующих или только удалённых файлов.
5. Проверьте `recovery-manifest.csv` и содержимое важных файлов.

Полный поиск не реконструирует все структуры файловой системы. Повреждённый загрузочный сектор или метаданные могут препятствовать распознаванию. Резервные загрузочные секторы иногда появляются как отдельные кандидаты.

Экспорт использует список метаданных `fls` и чтение содержимого `icat`. Каждый запуск получает новый `recovered-tree-NNNN`; прежние результаты не перезаписываются. Недопустимые для Windows имена, совпадения регистра, конфликты файла и каталога и повторяющиеся имена получают допустимые уникальные варианты. В CSV сохраняется соответствие исходного и итогового пути.

При утере родительской записи часть файлов попадёт в `$OrphanFiles`. NTFS ADS, ссылки и специальные записи пропускаются с записью причины. Не все длинные пути поддерживаются; ошибка отдельного файла отражается в отчёте. При частичном экспорте содержимое сохраняется как `.partial-...`, а остальные файлы продолжают извлекаться.

`Recovered` означает, что операция извлечения завершилась и размер соответствует метаданным. Это не проверка формата и не доказательство исходного содержимого. Открывайте важные документы, проверяйте архивы и сверяйте известные хеши.

## PhotoRec

Если метаданные не позволяют извлечь нужные файлы, выберите PhotoRec. Он ищет известные сигнатуры в образе и сохраняет результат отдельно в `carving-NNNN`. Исходные имена и папки этим методом обычно не восстанавливаются. Интерфейс PhotoRec и внутренние отчёты TSK могут быть на английском.

## Поддержка и ограничения

Испытаны FAT16, FAT32, exFAT, NTFS на файлах образов. Быстрое обнаружение других файловых систем зависит от сборки TSK; для них нет такого же набора проверок. Ремонт ФС, реконструкция RAID, снятие шифрования, составные образы и универсальная работа с виртуальными дисками не входят в эту версию.

Полный перечень границ защиты источника приведён в [README](../README.md#защита-источника-и-пределы), а фактическая область испытаний — в [VERIFICATION.md](VERIFICATION.md).
