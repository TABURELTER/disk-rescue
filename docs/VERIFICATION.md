# Область проверок Disk Rescue

Проверки восстановления выполнялись на **файлах образов**, без открытия реальных физических устройств. Для проверки содержимого использовались заранее известные SHA-256 и опубликованные автором испытательного NTFS-образа MD5. Успешный код выхода сам по себе не считался доказательством корректного восстановления.

Ниже описана проверенная база версии 2, на которой основана публичная версия 2.1. Изменения публичной упаковки — установщик GitHub, отделение исходников и исключение частного лога DMDE. Хеш конкретной программы и сведения о сборке следует брать из `BUILD-INFO.json` соответствующего релиза. Базовые результаты сохранены в [verification-v2-baseline.json](verification-v2-baseline.json); они относятся к указанному в этом файле SHA-256 программы и не выдаются за повторное испытание любого будущего релиза.

Для публичной версии в репозитории есть переносимый набор [tests/](../tests/README.md): он создаёт собственные синтетические образы FAT16/FAT32/exFAT, проверяет экспорт побайтно, неизменность исходного образа, повреждённую MBR, небезопасные имена, отказ повторно использовать каталог назначения, анализ лога как данных и выход из меню. Команда запуска — `python tests/smoke.py --report dist/TEST-RESULTS.json`. Фактические результаты конкретного запуска содержатся в отчёте; наличие теста в исходниках само по себе не означает, что он пройден. NTFS, доступ к физическому устройству и аппаратные ошибки этим переносимым набором не проверяются.

## Восстановление по метаданным

| Сценарий | Проверка | Результат |
| --- | --- | --- |
| FAT16, FAT32, exFAT: сырые тома и MBR-варианты | 6 образов × 6 обычных файлов; известные SHA-256 | 36/36 содержимых совпали |
| FAT32 с MBR, начало тома на секторе 2048 | Конечный самостоятельный PS1; вложенные Unicode-пути, фрагментация и пустой файл | 6/6 SHA-256 совпали |
| exFAT с уничтоженным сектором MBR | Полный поиск загрузочных секторов | Ожидаемая ФС найдена на секторе 2048 |
| NTFS с удалёнными файлами | Сравнение с опубликованными MD5 автора образа | 8/8 обычных файлов совпали |
| Недопустимые и конфликтующие Windows-имена | Содержимое каждого файла и допустимость итоговых путей | 14/14 SHA-256 совпали, без перезаписи |

Синтетические FAT/exFAT-образы содержали:

- Вложенные русские папки и длинные русские имена.
- Одинаковые базовые имена в разных папках.
- Пустые файлы и директории.
- Фрагментированный двоичный файл длиной 13 577 байт.
- Варианты с таблицей MBR и смещением 2048 секторов.

В испытании небезопасных имён использовались `CON.txt`, различия регистра, завершающие точки и пробелы, конфликт файла и каталога, одноимённые существующая и удалённая записи и имя с `..\`. Проверялось, что содержимое каждого файла остаётся внутри нового каталога результатов и не перезаписывает другое содержимое. Исходное имя и итоговый путь связываются в CSV.

## NTFS: независимый эталон

Использован [официальный испытательный образ из репозитория The Sleuth Kit](https://github.com/sleuthkit/sleuthkit_test_data/tree/main/from_brian): `7-undel-ntfs.zip`, DFTT test 7, Brian Carrier, 2004. Прилагаемый к образу `index.html` содержит ожидаемые MD5. MD5 исходного образа: `e7dbb96759d9cd62b729463ebfe61dab`.

Проверены resident и nonresident данные, одно- и многокластерные файлы, фрагментированные данные и вложенные удалённые директории. У одной записи исходный родитель уже утрачен: файл корректно извлекается под `$OrphanFiles`, а не под недостоверно восстановленным прежним путём.

Девятый поток, NTFS ADS, намеренно не экспортируется и отмечается в CSV как пропущенный. Таким образом, результат «8/8» относится к обычным файлам и не утверждает поддержку ADS.

## Терминальное меню и PhotoRec

Проверен сценарий: открытие образа с русским именем и пробелами → поиск ФС → список → поиск по пути → листание → экспорт → возврат → выход. Процесс завершился с кодом 0; повторное использование уже существующей папки назначения отклонено.

PhotoRec проверен на отдельном синтетическом образе. Извлечённые PNG и ZIP совпали по SHA-256 с заранее известным содержимым.

В перечисленных сценариях хеши исходных образов до и после операций совпали. Экспортёр также испытан в Windows PowerShell 5.1 с `Set-StrictMode -Version Latest`.

## Проверка происхождения движков

Оригинальные TSK-архивы получены из [официального релиза 4.15.0](https://github.com/sleuthkit/sleuthkit/releases/tag/sleuthkit-4.15.0). SHA-256 Windows ZIP и архива исходников совпали с digest-метаданными релизных файлов GitHub. Хеши оригинальных и изменённых четырёх TSK EXE записаны в `utf8-manifest-patches.json` внутри движков и в информации о сборке.

В этих EXE изменён ресурс application manifest: добавлен `activeCodePage=UTF-8`. Исполняемый код не изменялся намеренно. Требование Windows 10 1903+ связано с [поддержкой UTF-8 code page в manifest](https://learn.microsoft.com/en-us/windows/apps/design/globalizing/use-utf8-code-page). DLL скопированы из официальных архивов без изменений. Исходники и лицензии сохранены рядом с движками.

## Что не испытано и не гарантируется

- Реальные физические диски не открывались. Нативный модуль чтения скомпилирован, но успешное копирование настоящего накопителя, запросы его размера и серийного номера не испытаны на устройстве.
- Не испытаны все типы USB-адаптеров, физические ошибки чтения, нестабильное питание и накопители с деградацией.
- Синтетические повреждения не моделируют всё разнообразие повреждений реального диска.
- Совпадение размера извлечённого файла не подтверждает его целостность; перезаписанные кластеры могут содержать другие данные.
- Проверки образов не доказывают отсутствие записи со стороны Windows, драйверов или других приложений на подключённый физический носитель.
- Полное восстановление структуры, временных меток, ACL, атрибутов и всех файлов не гарантируется.

Инструкции используют условные пути и имена тестовых данных. Частный DMDE-лог, серийные номера пользовательских устройств и локальные пути автора в публичные материалы не включены.
